THE PROBLEM
───────────
Session declared "COMPLETE" while 46 files remained uncommitted and no observations 
were logged. This broke session continuity - the core purpose of Wheelwright.

LESSON LEARNED
──────────────
"Complete" does NOT mean: Code + tests + docs done
"Complete" DOES mean:     Code + tests + docs + GIT COMMITTED + OBSERVATIONS LOGGED

THREE-LAYER MITIGATION
──────────────────────

LAYER 1: Automated Validator (wai/closeout_validator.py)
        ├─ Checks git status is clean
        ├─ Verifies observations logged
        ├─ Confirms commit exists from today
        └─ Provides immediate feedback

        Usage:
          $ python -m wai.closeout_validator --check
          ✓ PASS | Git Status Clean
          ✓ PASS | Git Commit Today
          ✓ PASS | Observations Logged
          ✓ SESSION CLOSEOUT COMPLETE

LAYER 2: Mandatory Checklist (CLOSEOUT-CHECKLIST-TEMPLATE.md)
        ├─ Pre-closeout verification
        ├─ Git commitment phase (5 steps)
        ├─ Observations logging phase (3 steps)
        ├─ Validation phase (1 step)
        └─ Final verification (7 checks)

        Gates session completion - can't skip steps

LAYER 3: Protocol Gate (AGENTS.md)
        └─ Critical section added to AGENTS.md
           Do not declare "complete" without:
           1. git status shows "working tree clean"
           2. observations.jsonl has ✓ COMPLETE entry
           3. validator --check passes all 3 checks

HOW IT PREVENTS THE MISTAKE
────────────────────────────

BEFORE (What Would Happen)
  Session done → Declare "COMPLETE" ❌
  [No git validation]
  [No observation check]
  [46 files uncommitted]
  [Next session confused]

AFTER (What Happens Now)
  Session done → Run validator → Shows 3 passing checks ✓
  [Git status: clean]
  [Observations: logged]
  [Can now safely declare COMPLETE]
