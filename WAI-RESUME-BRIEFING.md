### Item 2: Session Ledger — New WAI Pattern

**Priority:** High — install this BEFORE doing remaining work so the remaining
work is itself tracked by the ledger. Dog-food the pattern.
**Estimated effort:** 1-2 hours

**What it is:**

A session ledger is an append-only log of what was requested, what was agreed to,
and what was delivered. It lives per-node as `WAI-Ledger.jsonl` alongside
WAI-Lugs.jsonl. Each entry records a commitment and its resolution.

**Why it exists:**

During WAI v2 migration, token exhaustion and a crash caused context loss.
The executing agent reconstructed intent from partial memory, renamed core
concepts (PEV → perspective/evidence/verdict), skipped two phases, and
declared the migration complete. There was no mechanism to detect the drift
because commitments lived only in conversation context, not in files.

The session ledger ensures that what was asked for and what was agreed to
is recorded in the filesystem, surviving any context loss. On session resume,
the agent reads the ledger and can verify: "Was this commitment fulfilled?"

**Schema:**

```jsonl
{"id":"led-2026-02-12-001","timestamp":"2026-02-12T14:00:00Z","session_id":"session-001","type":"request","content":"Migrate Lug schema to v2 with PEV fields","source":"conductor","status":"open"}
{"id":"led-2026-02-12-002","timestamp":"2026-02-12T14:05:00Z","session_id":"session-001","type":"agreement","content":"Will add perceive/execute/verify as optional fields, map v1 statuses, preserve originals in _v1_* prefix","source":"agent","references":"led-2026-02-12-001","status":"open"}
{"id":"led-2026-02-12-003","timestamp":"2026-02-12T15:00:00Z","session_id":"session-001","type":"delivery","content":"Lug schema migrated: 350 Lugs upgraded, 134 signals absorbed, PEV fields added","source":"agent","references":"led-2026-02-12-001","commit":"73112e9","status":"fulfilled"}
```

**Ledger entry types:**

| Type | Who Creates | Meaning |
|------|-------------|---------|
| request | conductor | "I want this done" |
| agreement | agent | "I will do this, here's how" — records the commitment |
| clarification | either | "Do you mean X or Y?" / "I mean X" |
| amendment | either | "Actually, let's change the approach to..." |
| delivery | agent | "This is done" — links to commit hash |
| verification | conductor | "Confirmed" or "This doesn't match what was agreed" |
| rejection | conductor | "This doesn't fulfill the agreement, because..." |

**Ledger entry fields:**

```yaml
id: "led-{date}-{seq}"          # Unique identifier
timestamp: ISO 8601              # When this entry was created
session_id: string               # Which session this belongs to
type: enum                       # request, agreement, clarification, amendment, delivery, verification, rejection
content: string                  # What was said/agreed/delivered (plain language)
source: "conductor" | "agent"    # Who created this entry
references: string | null        # ID of the entry this responds to (threads the conversation)
commit: string | null            # Git commit hash (for deliveries)
status: "open" | "fulfilled" | "amended" | "rejected"  # Current state
lug_ids: [string] | null         # Lugs created to fulfill this request
```

**How it's used:**

On session start, the wakeup sequence includes:
1. Read WAI-Ledger.jsonl
2. Filter for status: "open" — these are unfulfilled commitments
3. Surface in the composite briefing: "Open commitments from prior sessions"
4. Agent can verify: "Agreement led-001 says I'll add PEV fields. Let me check if perceive/execute/verify fields exist."

On session close (as part of closeout/shipit):
1. session-observer reviews open ledger entries
2. For each: was it delivered? Create delivery entry with commit hash. Or: still open, carry forward.
3. Surface unfulfilled commitments: "These requests are still open from prior sessions"

On context loss / session resume:
1. New agent reads ledger
2. Compares open agreements against actual state of codebase
3. Identifies drift: "Agreement says PEV = perceive/execute/verify, but I see perspective/evidence/verdict in the code"
4. Creates diagnosis Lug for each discrepancy

**Integration points:**

- `WAI-Ledger.jsonl` lives alongside WAI-Lugs.jsonl in every node
- session-observer Skill gains a ledger reconciliation step
- Wakeup sequence surfaces open commitments
- Closeout/shipit verifies all session commitments resolved
- Composite briefing (CLAUDE.md) includes "Open Commitments" section
